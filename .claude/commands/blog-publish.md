description: Convert a finished blog source file into a published-ready post and open a PR
argument-hint: BL-xx
---
Publish blog $ARGUMENTS.

These are local tools only; none of them run in Cloudflare's build or in any
GitHub Actions workflow. Never push to main, never merge.

1. `git checkout main && git pull && git checkout -b blog/$ARGUMENTS-<slug>` (slug comes from
   step 2). If a branch with that name already exists, continue on it instead of recreating it.
2. Run `npm run ingest -- $ARGUMENTS`. It finds the matching source in `Content/Blogs/_Source/`
   (a `.docx`, read with mammoth, or a hand-written `_final_copy.html`; `.docx` wins if both
   exist), stops with a clear list of problems if it finds VERIFY/TODO/TBD, the all-caps word
   CONFIRM specifically, lorem ipsum, U+27E6/U+27E7, an em or en dash,
   `[DATE]`/`[LOGO_URL]`/`[OG_IMAGE_URL]`, an over-length title tag or meta description, or a
   structure it cannot map to an existing block type in `src/content/blogs/types.ts`.
   If it stops **and** a `_final_copy.html` with the same id exists in `Content/Blogs/_Source/`,
   re-run with `npm run ingest -- $ARGUMENTS --prefer=html` to use that clean copy instead, and
   tell me you did this and why. If it stops and no clean HTML copy exists, show me the problem
   list and stop here; do not try to work around the checker.
   If it succeeds, show me: the detected outline, every link it removed because the target isn't
   live, and the generated-schema-vs-source-schema differences.
3. Run `npm run images:make -- <slug>`. Show me the banner, og crop, and infographic (if any) it
   rendered. If I already dropped `public/images/insights/<slug>-banner.png`, it is used as-is.
4. Run `npm run check:blog -- <slug>`. Fix anything that fails by re-running ingest/images after
   correcting the source file, the Page details table, or (rarely) the mapping logic itself. Never
   weaken the checker to make a post pass.
5. Run `npm run lint` (tsc --noEmit) and `npm run build`. Fix everything that fails.
6. Prerender proof checks against the built output: the answer box text, one full FAQ answer, the
   tool block's text if the post has one, and every image's alt text are present in the built
   HTML; `/insights` lists the new post.
7. Take Playwright screenshots at 1440 and 390 width and show them to me.
8. Commit only code, content, the registry, and images (never `public/_snapshots/` or
   `public/sitemap.xml`, both are regenerated by CI). Push the branch and open a PR.
9. The PR description must include: the detected outline, links removed because the target isn't
   live, the schema diff, the image previews, a table of which checks passed, the Cloudflare
   preview link once it appears, and a short review checklist for me (CA sign-off on the content,
   confirm the images, confirm heroVariant/infographic were picked sensibly, click Merge myself).
   Do not merge it yourself.
10. End with a short list: anything in the source file that looked inconsistent, any claim without
    a source, and any decision I need to make (e.g. heroVariant or infographic looked uncertain).
